    What it is

    WyattCurtis327/mortgage-capital-markets-analytics is a public Databricks reporting and analytics pack for a fintech / nonbank capital markets desk that originates to sell. MIT license. Novice walkthrough: docs/README.md.

    Four desk questions: PT-weighted book and hedge policy; why econ moved; realized GOS; whether last night’s PT grid is still usable. The pack includes a gold star in Unity Catalog, a metric catalog with additivity rules, pull-through / attribution / MERGE SQL, annotated desk queries, a 10k sample lock tape, a FRED macro layer, lock-event extensions (renego / soft fallout), and a 15-minute decisioning agent.

    Not a trading system, LOS, or MISMO exchange. It does not connect to a live TBA desk or warehouse bank.

    Price convention: points (100 = par). Dollars = UPB × points / 100. Canonical docs: glossary, architecture, metrics, built vs missing.

    Why capital markets sits inside origination

    Origination manufactures the loan. Capital markets makes it fundable, hedgeable, and saleable. The economic clock starts at rate lock, not at closing. When the borrower locks, the company is long a fixed-rate mortgage that does not yet exist. If market prices fall before sale, that lock is worth less. The desk:

    • Feeds the product / pricing / eligibility (PPE) engine from TBA and investor bids.
    • Hedges the lock pipeline, usually by shorting TBA MBS, sized to pull-through-weighted exposure.
    • Arranges warehouse lines so closing can fund.
    • Runs best execution and delivers the loan.
    • Marks and optionally hedges MSRs if servicing is retained.

    Without that loop, origination quotes rates the secondary market will not pay and closes loans the balance sheet cannot carry.

    Deploy order

    1. Star + eligibility + lock events — sql/05_gold_star_ddl.sql, sql/06_eligibility_note_structure.sql, then sql/09_lock_event_extensions.sql (chain_id, margin give, soft-fallout flags).
    2. KPI views + PT forecast — sql/01_origination_kpis.sql, sql/02_pullthrough_forecast.sql. Empirical PT by status × channel × purpose × product × ITM bucket, shrunk toward a parent when the cell is thin (k = 40), plus a channel beta on price move. Price move P_now − P_lock > 0 means the market rallied and the lock is OTM for the borrower — PT should fall; beta is negative. Rebuild the grid nightly from resolved vintages, not the live open book.
    3. Nightly MERGE — sql/04_daily_merge_job.sql. Restate the last 5 days with MERGE + WHEN NOT MATCHED BY SOURCE delete. Freeze older partitions, including the PT used that day. FAIL: zero rows, bad UPB/PT, default-PT share > 20%, PTWLV shock > 35%. Coverage outside 70–120% is a WARN.
    4. Daily P&L attribution — sql/03_pnl_attribution.sql. Splits Δecon into new locks, fallout, fund PT step-up, market, PT revision, renegotiation, UPB change, residual. Offset = −hedge_pnl / (market + pt_revision). Do not put new locks, fallout, or renego in the denominator.
    5. FRED macro — sql/08_fred_macro.sql + databricks/fred_pull.py. Observation store plus calendar-daily linear fill (do not extrapolate past last print; is_interpolated flags invented points). Desk view: DGS10, SOFR, PMMS 30, pmms30_minus_dgs10. The pull needs a FRED API key in the job environment — not in git.
    6. Reporting examples — sql/07_reporting_examples.sql against gold_cm.

    15-minute agent (docs/agent-15min.md): Watcher every print or TBA jump → Analyst on WARN/FAIL → Reporter desk card. Last night’s PT grid is a prior. The agent drafts tickets (auto_execute: false). It does not refit the model at 10:15 and it does not send TBA orders.

    Model

    epa_home   = (home_net_epa - away_net_epa) * 65 + HFA
HFA        = 2.25 at home, 0 on international / neutral sites
model_home = 0.60 * nfelo_home_margin + 0.40 * epa_home + overlay
edge       = model_home - market_home_margin
market_home_margin = -spread_home     # home -3.5 → market margin +3.5
Play if |edge| >= 1.5 else Lean

    EPA window (n = completed REG games this season for that team, before the slate week):

    • n < 6 — last 12 REG games (may cross seasons)
    • n >= 6 — 50% last-8 + 50% last-k this season, k = min(17, n)

    PBP filter: play_type in {pass, run}, qb_kneel == 0, qb_spike == 0, EPA not null. nflverse PBP uses LA for the Rams.

    Overlay (OUT / will-not-play only): QB 4.0, WR1 1.5, LT 1.5. Home OUT subtracts from model_home; away OUT adds. Stack cap 6.0. Skip the QB 4.0 when that team’s nfelo |QB adj| ≥ 50.

    What it is

    WyattCurtis327/nfl-clv-ledger is a public Python CLI + DuckDB ledger for NFL ATS (and optional ML) picks. It logs open / bet / close prices and grades closing-line value (CLV) separately from win-loss. MIT license. No secrets or personal bet history in the tree.

    Closing-line value

    CLV asks: did you get a better price than the market’s final number before kickoff? Example: you bet Rams −3; the close ends −4. You beat the close by a point — positive CLV. That is good process even if the Rams lose ATS.

    Win rate over a small sample is mostly noise. Sustained positive CLV is the honest process metric against a sharp(ish) close.

    No-vig CLV

    Books build a margin (vig) into both sides. No-vig CLV strips that tax and compares fair implied probabilities. Units are probability points (no_vig_clv_pp).

    • Positive no_vig_clv_pp — you bought cheaper probability than the fair close.
    • Break-even at −110 is 52.38% implied (reference only, not a target).

    This ledger grades no-vig CLV and ATS W-L as separate lines. Never claim “beats the market” from W-L alone.

    Open / bet / close

    FieldMeaning
    OpenFirst usable line you saw (or book open) for that side
    BetPrice you actually took (or would have taken)
    CloseLast sharp-ish number before kickoff

    If Analytics looked at a slate and took zero plays, log an explicit no-bet row so empty weeks are intentional, not missing data.

    CLI

    nfl-clv init
nfl-clv add --from-csv samples/week1_sample.csv
nfl-clv set-close
nfl-clv grade --week 1
nfl-clv summary
nfl-clv export --week 1 -o week1.csv

    Default DB: ./ledger.duckdb, or NFL_CLV_DB. Schema: season | week | game_id | side | market | book | open_price | bet_price | close_price | timestamps | no_vig_clv_pp | result | notes. Market is ats or ml. Result is win / loss / push / pending / no_bet.

    Math (v1)

    American → implied: favorite (|a| / (|a| + 100)); dog (100 / (a + 100)). No-vig method is multiplicative: no_vig_a = p_a / (p_a + p_b). When a row logs only one side’s juice, v1 synthesizes the opposite at −110.

    no_vig_clv_pp = 100 × (close_no_vig_prob − bet_no_vig_prob)

    Positive means you bought cheaper no-vig probability than the fair close. Process ≠ profitability; never conflate CLV with ATS W-L.

    What it is

    WyattCurtis327/pricing-scenarios prices a slate of hypothetical mortgage loans against a daily rate sheet. You describe each scenario (program, product, lock period, amount, FICO, LTV, purpose). The notebook looks up every applicable price adjustment, stacks them onto the lock-period price, then solves for the par rate (the note rate where price adjustment ≈ 0).

    This is a workflow, not a live lock desk. Drop in a rate-sheet workbook, run the notebook, get a results CSV. No Databricks, no API keys. MIT license. Live rate sheets stay out of git.

    Workflow

    1. Drop today’s workbook in ./data/.
    2. Set fileName in the notebook (or rename to match).
    3. Run all cells.
    4. Read {date}_Pricing Scenarios_Results.csv.

    For each scenario the notebook flags the product, sums every matching adjustment (ADJ_TOT), melts lock-period prices, adds the stack to the curve, then solves par:

    • If the adjusted curve straddles par, interpolate the two neighboring points linearly (lineRATE).
    • Otherwise fit price ~ a * ln(rate) + b and fsolve for price = 0 (logRATE).
    ADJ_TOT = ADJ_LoanAmt + ADJ_FICO + ADJ_HIGH_BAL
        + ADJ_GT_15 + ADJ_COR + ADJ_PRICE_SPECIAL
        + ADJ_LPMI_TERMS + ADJ_LPMI_AMORT_LTE_25 + ADJ_LPMI_COR
adjusted_price = rate_sheet_price(lock) + ADJ_TOT
par rate       = rate where adjusted_price ≈ 0
